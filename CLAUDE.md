# Tangent: notes for Claude

- Live site: https://tangentreads.com (Cloudflare Pages project `tangent`, Git-connected; www and the old tangent.szumlanski.com redirect there via `functions/_middleware.js`). `app/_routes.json` decides which paths run functions: add any new function route to it. Pushing to `main` deploys; there is no build step and the output directory is `app/`.
- Always merge finished work to `main` and push to deploy. Do not ask Jason first.
- The web app is `app/index.html` (UI, CSS, JS). Keep it one self-contained file with no outside scripts or fonts so it stays fast and works offline.
- The fetcher is Node in `fetcher/`, run by `.github/workflows/fetch.yml`: each run loops for about 5h40m and fetches every 15 min (GitHub's own schedule fires hours late), pulling new code between rounds. Run `npm test` and `DRY=1 npm run fetch` before pushing fetcher changes. Behind the cloud proxy, set `NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt`.
- Story grouping is free and local (`fetcher/match.js`, word matching across different outlets). Only multi-outlet stories get a Claude summary (`fetcher/stories.js`, `claude-haiku-5-5`). Jason cares about API cost: never send Claude data on every run that a local step can handle, and estimate monthly cost before adding any model call.
- `functions/api/chart.js` and `functions/api/espn.js` are Pages Functions (free plan: keep CPU light, cache at the edge). The service worker must never cache `/api/`.
- The engine (shelves are interests, not source lists): every article is enriched in the fetcher for free (`fetcher/enrich.js`: an all-MiniLM-L6-v2 meaning vector via transformers.js, topic labels from `fetcher/taxonomy.js`, junk flags and quality in `fetcher/classify.js`). Each shelf links to a shared `tangent_interests` row (phrase, topic or place); `fetcher/interests.js` gives it a vector. `tangent_shelf_rank` (SQL, latest in the highest-numbered migration that defines it) recalls by meaning, keyword and the shelf's own sources, scores relevance x quality x freshness x story size x engagement x the persona's taste, keeps one card per story and damps any one source; the app (`GET /api/v1/shelves/rank`) shows its order and the reason (`why`). Region shelves go through `tangent_region_rank` (places from the Census gazetteer in `tangent_places`). SW Florida and Vermont catalog shelves stay in `follow` mode (their own sources, `tangent_shelf_feed`).
- Discovery: every followed phrase gets YouTube search and Hacker News feeds (`fetcher/strategies/discover.js`, created by `tangent_ensure_discovery`). Local TV and radio sources with `selectors.local` drop non-local wire stories (`fetcher/local.js`, stored with `offtopic`); `selectors.skip` drops URL sections.
- Readers teach shelves: votes and hides (persona taste, on the server), "Not about [shelf]" (`tangent_shelf_rejects`) and "Hide [source]" (`tangent_persona_mutes`). A daily Haiku check (`fetcher/quality.js`, about $0.15 a month, capped by `judge_cap`) rates each shelf's top 20; see the admin Quality tab.
- Database: Supabase project EG4 Monitor (`kyplwgcvbfzyfhiyspsr`). It is a live customer database for another app. Only ever touch objects prefixed `tangent_`. Add schema changes as new files in `supabase/migrations/`.
- Push alerts: `fetcher/alerts.js` runs after each fetch, matches new stories to `tangent_alerts` locally (no AI) and sends Web Push with VAPID keys from `tangent_config`; `tangent_alert_sent` stops repeats and logs every push. The service worker shows them and opens `/#a=<article id>`.
- Paywalled articles must never show. Exception by design: sources with `access = 'subscriber'` (papers the reader chose to follow, like the Manchester Journal) store only headline, teaser and photo (`locked = true`) and link out; their text is never fetched or shown. Detection is per article in `fetcher/paywall.js` and `fetcher/extract.js`; the `tangent_articles` RLS policy also hides `paywalled = true` rows.
- After changing anything in `app/`, bump `CACHE` in `app/sw.js` (tangent-vN) so installed copies refresh.
- Logo: `design/logo.svg` is Jason's master file (keep it as given). Derived from it: `icon.svg` (app icons), `icon-maskable.svg` (Android, mark only), `fav.svg` (favicon), `mark.svg` (masthead mark in the app and site pages; copy to `app/`). The master's glow filter draws a gray box around the dot, so the derived files use a plain halo instead. Re-render the PNGs with Playwright after edits (Inter as the wordmark font). If an icon changes, give the PNGs new file names, because `app/_headers` lets browsers cache PNGs for a week.
- Before pushing, render with Playwright at 390px (light and dark) and 1280px, read the screenshots, and confirm zero console errors and no horizontal scroll.
- Follow `docs/hig-notes.md` (44px targets, 17px body text, 4.5:1 contrast, sentence case). Avoid generic AI-looking design.
- Never use em dashes in UI copy, code comments, commits or replies.
- Free services only. The only key in the page is the Supabase publishable key, which is public by design; RLS guards the data.
